# 复习测验:一次只改一件事

- 课程:与 AI 搭档开发(`build-with-ai`)
- 课时:Change one thing at a time(`iterate-in-small-steps`)
- 题型:单选

## 第 1 题

每一次改进的正确顺序是什么?

- A. 提出请求、检查、保存、重复
- B. 一次提出所有请求,然后保存,最后检查
- C. 先发布,再检查
- D. 先删除旧文件,再提出请求

**答案:A**

解析:每次只做一件事,检查通过后保存,再从保存的状态开始下一次请求。

依据:The loop

## 第 2 题

为什么要强调“其他都不要动”?

- A. 这样助手会运行得更快
- B. 未被要求的改动会掩盖真正的问题,使检查更加困难
- C. 这样就可以跳过提交步骤
- D. 这样 GitHub Desktop 会自动关闭

**答案:B**

解析:每个未被要求的改动都会让下一次检查更难,也可能隐藏真正的错误。

依据:Why "change nothing else" matters

## 第 3 题

在 GitHub Desktop 中提交之前,你应该做什么?

- A. 直接提交,不查看改动
- B. 查看改动列表,确认没有意外出现的文件
- C. 删除所有以前的提交
- D. 把文件夹改名为 `hello`

**答案:B**

解析:提交前查看改动,可以及时发现不应该出现的文件或多余的修改。

依据:What you will do

# 复习测验:小组协作

- 课程:毕业项目：做出并上线你自己的应用(`capstone-project`)
- 课时:Work on a project with others(`team-collaboration`)
- 题型:单选

## 第 1 题

小组协作时,为什么要用分支和 Pull Request?

- A. 为了让文件变大
- B. 为了不用提交
- C. 为了让别人看不到改动
- D. 让每个人的改动先被审阅,再合并进主线

**答案:D**

解析:这样主线能保持可用,改动也有人把关。

## 第 2 题

审阅组员的 Pull Request 时应该做什么?

- A. 读完改动,并留下具体的意见
- B. 不看直接点同意
- C. 直接关闭
- D. 只看标题

**答案:A**

解析:审阅的价值在于真的读过改动。

## 第 3 题

合并时出现冲突,最合理的做法是什么?

- A. 随便删掉一边
- B. 弄清两边各改了什么,再决定保留哪部分
- C. 重装电脑
- D. 忽略并继续

**答案:B**

解析:冲突是两处改动碰到了同一个地方,需要人来判断取舍。

# 复习测验:发起 Pull Request 并查看改动

- 课程:GitHub 协作:分支与 Pull Request(`github-collaboration`)
- 课时:Open a pull request and read the changes(`open-a-pull-request`)
- 题型:单选

## 第 1 题

草稿(draft)状态的 Pull Request 能否直接合并?

- A. 能,草稿和普通 Pull Request 没有区别
- B. 不能,草稿不能合并,需要先标记为可以审阅
- C. 只能在周末合并
- D. 只能由 GitHub 自动合并

**答案:B**

解析:官方说明草稿不能合并,标记为可以审阅之后,代码所有者才会被自动请求审阅。
依据:Write a clear description

## 第 2 题

在 Files changed 中审阅时,标记 Viewed 的作用是什么?

- A. 删除这个文件
- B. 提交当前的改动
- C. 收起已读的文件,并让页面顶部的进度条前进
- D. 把改动推送到 GitHub

**答案:C**

解析:标记 Viewed 会收起这个文件,并更新页面标题栏中的进度条,方便你记住已经读过哪些文件。
依据:Review the changes one file at a time

## 第 3 题

合并到 main 之后,电脑上的 main 要怎样更新?

- A. 在 GitHub Desktop 中选中 main,点击 Fetch origin,再点击 Pull origin
- B. 删除电脑上的仓库
- C. 重新创建一个分支
- D. 什么都不用做

**答案:A**

解析:合并发生在 GitHub 上,只有获取并拉取之后,电脑上的 main 才会包含你的工作。
依据:Bring main up to date on your computer

A projects section shows the things you have made, so a visitor sees your work quickly. In this lesson you add or improve it, one small request at a time. By the end your site will show your three projects clearly, and each change will have its own save point.

## What a good projects section needs

- A clear heading, such as "Projects".
- Three entries, each with a title, a one or two sentence description and, if you have one, a link or a picture.
- The same layout for every entry, so the section looks tidy.

## What you will do

1. Open the site and look at your current projects section. Note what you want to change.
2. Ask for one change only, such as: `Show each project as a card with a title and a short description. Keep the rest of the page exactly as it is.`
3. Reload the page and look at the result.
4. If it is right, commit in GitHub Desktop with a description such as `Project cards`. If it is not, say what is wrong in one sentence and ask again.
5. Ask for a second change, for example: `Add a link on each project title. Use the link text I give you for each project.` Supply the link text yourself, so the assistant does not invent addresses.
6. Check that each link goes where you expect, then commit again.
7. Ask for a third change of your choice, such as spacing, colours or the order of the projects.

## About links and pictures

Use only pictures you own or are allowed to use. If the assistant suggests an address you do not recognise, do not keep it. Ask it where the address comes from, or leave a clear placeholder and fill it in yourself.

## Check yourself

- The site shows three projects in the same layout.
- Every link goes where you expect.
- You made at least two commits in this lesson, each describing one change.

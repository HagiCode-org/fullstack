In this lesson your AI assistant builds the first version from your brief. You run it, look at it, and compare it with your done checklist. The first version does not need to be beautiful. It needs to run.

## What you will do

1. Open your project folder with your AI assistant, and give it your brief. Ask it to build only the first version: add an item, show the list, remove an item.
2. Ask the assistant how to start the app on your computer, and which address to open in the browser. Read what each command does before you run it. If a command deletes files or installs something you do not recognise, ask the assistant to explain it first.
3. Run the start command in a terminal, inside your project folder. If you have not yet learned to open a terminal, the lesson "Your first look at the terminal" in the course Docker for Beginners shows you how. Use the instructions for your system:
   - On Windows, open the terminal the way that lesson shows, and run the Windows command the assistant gives you. If the assistant gives you only one command, ask it for the Windows version.
   - On Mac, open the terminal the way that lesson shows, and run the Mac command. If the assistant gives you only one command, ask it for the Mac version.
4. Open the address in your browser and try the app, as in the finished example.
5. Go through your done checklist. Tick each "I can" sentence that works, and write down each one that does not.
6. If something is broken, copy the exact error text from the screen or from the terminal where you started the app, and give it to the AI. Say what you expected to happen.
7. When the first version works, save a [checkpoint](../../../glossary/#first-web-app-checkpoint). In GitHub Desktop, commit the changes with a message such as "First version works".

## Why a checkpoint helps

Each commit gets its own identifier. [GitHub's guide to committing](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop) says that Git assigns each commit a unique ID, which identifies the specific changes, when they were made and who created them. That is what makes a commit useful as a checkpoint: you have a fixed copy of the working version that you can return to if a later change goes wrong.

If the AI wants to add accounts, payments or any online service, say no for now. That is not in your brief.

## Check yourself

- The app starts and opens in your browser.
- You can add and remove an item.
- You committed the working first version, so you can come back to it.

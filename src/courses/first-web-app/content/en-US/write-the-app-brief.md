An AI assistant builds what you describe, so a clear description gets a better first version. A [brief](../../../glossary/#first-web-app-brief) is a short written description of what you want the app to do. In this lesson you write the brief for your app, together with a [done checklist](../../../glossary/#first-web-app-done-checklist): a list of sentences that tells you when the app is finished. You will use both documents in every lesson that follows.

## Why write it down

The assistant only knows what you tell it, and a conversation can be hard to find again later. A file in your project folder stays where you put it, and you can open it in any new conversation. When you save a version of it, GitHub Desktop asks you for a commit message. [GitHub's guide to committing in GitHub Desktop](https://docs.github.com/en/desktop/making-changes-in-a-branch/committing-and-reviewing-changes-to-your-project-in-github-desktop) says that a commit must include a commit message that briefly describes the changes.

## What you will do

1. Write one sentence about who uses the app and why. Example: "I use it to see where my money goes each week."
2. List what the app must do, in short sentences. Keep the list small, five items at most. Example: "I can add an expense with a name, an amount and a date."
3. List what the app does not do yet. Examples: no login, no sharing, no charts. This protects you from a first version that is too big.
4. Write what it should look like, in plain words: simple, readable on a phone, large buttons.
5. Write the done checklist. For each item on your list, write one sentence that starts with "I can". The app is done when every sentence in the checklist is true when you test it.
6. Ask your AI assistant: "Here is my brief. What is unclear or missing? Ask me questions before you build anything." Answer its questions and update the brief.
7. Save the brief in your repository as a file, and commit it in GitHub Desktop with a message such as "Add app brief", so you can come back to it.

## Keep personal data out

Do not put real personal data in your brief, such as bank details, account numbers or passwords. When you give the AI examples, use made-up numbers. For example, "a coffee costs 3.50" is enough to show the idea. The assistant does not need your real information to build a working app.

## Check yourself

- Your brief fits on one screen and has a "does not do yet" list.
- Your done checklist has one "I can" sentence for each thing the app does.
- You answered the AI's questions, and the brief is saved in your repository.

This is the final project of the series. You will build one small app of your own, starting from an empty folder and ending with something other people can open in a web browser. Before you write any prompt or any code, you choose what to build and make it small enough to finish. In this lesson you pick the project, give it a name and write one sentence that says what it is for. You finish with that sentence and an empty repository on GitHub, which is a project folder that GitHub keeps for you.

## Why a small project works

Every project has a [scope](../../../glossary/#capstone-project-scope): the list of things it will do and the things it will leave out for now. A large scope is the most common reason a student project is never finished. A small scope with a clear end is much more likely to be done, and a finished small app teaches you more than an unfinished large one. The app in Your First Web App worked because it had one clear job, and your final project should have one clear job too.

## What you will do

1. Read the four suggested projects.

   **Resume maker.** A page where a person fills in their details and gets a clean resume they can save.

   **Notes app.** A place to write, find and delete short notes that are still there the next day.

   **Task board.** Columns such as "to do", "doing" and "done", with cards you can move between them.

   **Q&A helper.** A page where a person asks a question and gets an answer based only on text you provide.

2. Pick one of these, or describe your own idea in two sentences. Say who uses it and what they do with it. Your own idea is fine as long as you can explain it in two sentences.
3. Make it small. Ask yourself what the smallest version is that still helps one real person. Cut everything else for now.
4. Name the one person you are building for. It can be yourself. A project with one clear user is easier to finish than a project meant for everybody.
5. Ask your AI assistant: "Here is my project idea. Tell me what is too big for a first version, and what I could leave for later." Read the answer, then decide for yourself what to remove. The assistant gives advice, and you make the choices.
6. Write down at least three things you will not build in the first version. Keep this list. You will copy it into the spec in the next lesson.
7. Choose a short repository name. GitHub's guide says a repository name must not be longer than 100 characters and can only contain ASCII letters, digits, and the characters `-`, `_` and `.`. A name such as `notes-app` works well.
8. Create the repository on GitHub. Type the name and an optional description, then create it. GitHub's guide says a repository can be created on your personal account or on any organization where you have permission. If you want to work on it from your computer, you can also create it from GitHub Desktop, as the lessons in GitHub Desktop and GitHub showed you.
9. Write your one-sentence goal in the description field.

## Write the goal in one sentence

Use this pattern: "My app helps [person] to [do one job]." For example: "My notes app helps a busy student keep short notes that are still there the next day." If your sentence needs the word "and" twice, the project probably has more than one job. Cut the second job for now, and write it on your list of things you will not build.

## Common mistakes

Students who get stuck in this lesson usually make one of three mistakes. The first is choosing a project that needs accounts, payments and a server in its first version. Those features can wait for a later version. The second is writing a goal that describes the finished product you dream of, instead of the first version you can finish. The third is starting to build before you have named the person who will use the app.

## What if you cannot decide?

Pick the idea that you could explain to a friend in one minute. If two ideas are tied, choose the smaller one. You can always build a second project later, and the skills you practise in this project will be the same.

## Check yourself

- You chose one project and can explain it in one sentence.
- You named the one person who will use it.
- You wrote down at least three things you will not build in the first version.
- The repository exists on GitHub and its description holds your goal.

## What comes next

The next lesson is **Write the spec**. There you turn your goal and your list of things you will not build into a written spec, with a checklist that tells you when the first version is finished.

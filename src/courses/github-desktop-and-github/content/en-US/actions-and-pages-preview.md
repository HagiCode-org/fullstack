GitHub can do more than store files. **GitHub Actions** runs tasks for you automatically whenever something happens in a repository, such as checking your project each time you push. **GitHub Pages** can turn the files in a repository into a public website. In this lesson you will take a first look at both, without setting anything up in depth. Later courses use them to publish real websites, so the goal here is only to recognise them.

## What you will do

1. Open any popular open-source repository on GitHub and find its **Actions** tab. Look at one finished run. A green mark means the automatic checks passed and a red mark means one failed. Open a failed run and read where it stopped.
2. Ask your AI helper: "In three sentences, what does an automatic check on every pull request protect me from?" Compare its answer with what you saw.
3. Open the project page of a documentation site that is hosted with GitHub Pages, and notice that its address is a normal website address, even though the files come from a repository.
4. In your practice repository, look at the settings area and find the part about Pages. Read what it says, but do not switch anything on yet. You will do that in the publishing course.
5. Note one automatic check you would like for your own projects, for example "check that the website still builds before I merge".

**Safety note:** a Pages site is public. Do not publish a repository that contains private information.

## Check yourself

- You can find the Actions tab and tell a passed run from a failed one.
- You can explain in one sentence what GitHub Pages does.
- You know where the Pages settings live in a repository.

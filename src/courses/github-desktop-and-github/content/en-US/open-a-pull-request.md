A **pull request** asks to bring the work from your branch into `main`. Before that happens, the page shows exactly what changed, which gives you one calm place to review the work. It is the most important habit in this course: you do not need to understand how every line works, but you must look at what an AI helper changed before you accept it. In this lesson you will open a pull request for the branch from the last lesson and review it.

## What you will do

1. In GitHub Desktop, use the option to create a pull request from your branch. Your browser opens the GitHub page for it.
2. Write a title and a short description: what you changed and why. Ask your AI helper to help you word it, then check that it is true.
3. Open the tab that shows the changed files. Lines that were added are marked in one colour and lines that were removed in another.
4. Read every change. For each file ask yourself: did I expect this change? If something looks surprising, ask your AI helper: "Why was this line changed, and is it needed?"
5. Look for anything that should never be shared, such as passwords, keys or personal information. If you find any, do not merge.
6. If you are satisfied, merge the pull request, which brings the work into `main`. Then update your copy in GitHub Desktop, so `main` on your computer matches GitHub.

**Safety note:** the more files an AI changes in one go, the harder the review. Prefer small pull requests that change one thing.

## Check yourself

- You opened a pull request and wrote a clear description.
- You read all of the changes before merging.
- `main` on GitHub and on your computer now contain your work.
